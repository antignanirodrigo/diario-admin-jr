NAT: um IP Público para Muitos Privados

NAT muda o envelope do pacote, mas precisa lembrar para quem entregar a resposta

ANTES DE ALTERAR, OBSERVE. DEPOIS DE ALTERAR, VALIDE.

1. O chamado

#6601 PRIORIDADE BAIXA 10:00 aberto por: estagiário de infra
host: toda a rede interna, atrás do roteador · serviço: conceito de NAT
"Como todo mundo sai para a internet se cada PC tem IP privado?"
Até 50 máquinas atrás de um único roteador, nenhuma com IP público próprio — e todas acessam a internet normalmente. Como isso é possível?

💡 Passa o mouse nas palavras destacadas pra ver uma dica rápida — clica se quiser a explicação completa com analogia.

2. Antes de ver as opções — tenta responder

🧠 Recall ativo: o que o roteador troca no pacote quando ele sai da LAN pra internet, e como ele sabe pra quem devolver a resposta?
NAT troca o IP:porta de origem do pacote (ex: 192.168.10.15:51544) pelo IP:porta público do roteador (ex: 203.0.113.5:40001). O roteador guarda essa tradução numa tabela de conntrack — quando a resposta chega, ele consulta a tabela e sabe devolver pro cliente interno certo.

6. Procedimento profissional

  1. Confirme o IP privado real da máquina com ip -4 addr show.
  2. Compare com o IP visto de fora, usando um serviço de checagem externa (checkip).
  3. Use conntrack -L pra ver as traduções NAT ativas em tempo real.
  4. Entenda que a tradução é temporária, criada na saída e removida ao terminar a conexão.
  5. Nunca trate NAT como "mágica" — é sempre tradução rastreável de endereço e porta.

7. Laboratório guiado — marca conforme for testando

Segurança: execute os testes apenas em VM descartável e confirme nomes de discos, hosts e arquivos antes de cada comando.
  1. Em VM de laboratório atrás de NAT, confirme o IP privado com ip -4 addr show.
    $ ip -4 addr show eth0
    🔍 Detalhar esse comando
    ip addr show
    Mostra os endereços IP configurados nas interfaces de rede da máquina.
    -4
    Filtra a saída para mostrar só endereços IPv4, ignorando IPv6 — deixa o resultado mais limpo pra este laboratório.
    eth0
    Nome da interface a inspecionar — a que liga esta VM à LAN atrás do roteador NAT.
    Resultado esperado: endereço na faixa privada (ex: 192.168.x.x).
    Por quê: antes de comparar com o que o mundo externo vê, você precisa confirmar exatamente qual IP privado esta máquina usa por dentro.
    Cilada comum: rodar o comando na interface errada (ex: lo ou uma interface sem IP) e concluir que a máquina "não tem IP" — confira o nome real da interface primeiro com ip -4 addr show (sem especificar interface).
  2. Acesse um serviço de checagem de IP externo e compare com o IP privado.
    $ curl -s https://checkip.example
    🔍 Detalhar esse comando
    curl
    Faz uma requisição HTTP e imprime a resposta — aqui, um serviço que devolve o IP de origem que ele enxergou na requisição.
    -s
    Modo silencioso — esconde barra de progresso e estatísticas, mostrando só a resposta (o IP) na saída.
    Resultado esperado: IP público diferente do IP privado interno.
    Por quê: é a prova concreta de que o mundo externo enxerga o IP do roteador, não o IP privado da sua VM.
    Cilada comum: achar que o IP retornado é "da sua máquina" — na verdade é o IP público do roteador NAT, a máquina interna nunca aparece diretamente na internet.
  3. No roteador/gateway (se tiver acesso), rode conntrack -L e observe as traduções ativas.
    $ conntrack -L | grep 203.0.113.5
    🔍 Detalhar esse comando
    conntrack -L
    Lista (List) todas as conexões atualmente rastreadas na tabela de tradução do kernel.
    | grep 203.0.113.5
    Filtra a lista completa só para as linhas que envolvem o IP público do roteador — evita rolar por conexões de outras origens.
    Resultado esperado: lista de conexões com src interno e IP público de saída (ex: src=192.168.10.15 sport=51544 → src=203.0.113.5 sport=40001).
    Por quê: é a evidência direta de que a tradução acontece — sem essa tabela, o roteador não saberia devolver a resposta pro cliente certo.
    Cilada comum: rodar conntrack -L na VM cliente em vez de no roteador — a tabela de tradução vive no dispositivo que faz o NAT, não em cada máquina interna.
    🧑‍🏫 Aqui entra o Mentor (em breve): se conntrack não mostrar nada, este é o ponto onde o chat com o Sênior-IA vai ajudar a confirmar se o módulo de rastreamento está carregado.
  4. Abra duas conexões simultâneas de máquinas internas diferentes e compare as portas de origem na tabela.
    $ conntrack -L | grep 203.0.113.5 src=192.168.10.15 sport=51544 → src=203.0.113.5 sport=40001 src=192.168.10.22 sport=51545 → src=203.0.113.5 sport=40002
    🔍 Detalhar esse comando
    mesmo comando do passo anterior, chamado de novo
    Com duas conexões ativas ao mesmo tempo, a mesma consulta agora mostra duas linhas — cada uma com uma porta externa (sport) diferente, mesmo IP público.
    Resultado esperado: portas de origem externas diferentes para cada conexão.
    Por quê: é exatamente essa diferença de porta que permite ao roteador diferenciar respostas simultâneas usando um único IP público.
    Cilada comum: abrir as duas conexões em momentos muito distantes um do outro e a primeira já ter expirado da tabela antes de você comparar — mantenha as duas ativas ao mesmo tempo.
  5. Documente o modelo completo: LAN privada → roteador NAT → internet — reproduzindo o painel 6 da prancha de hoje.
    Resultado esperado: diagrama e explicação clara do fluxo de tradução.
    Por quê: registrar o modelo mental completo agora evita confusão mais adiante, quando você configurar SNAT e DNAT manualmente com nftables.

8. Validação e encerramento

  • O IP privado e o IP público foram confirmados como diferentes.
  • A tabela de conntrack foi observada, mostrando traduções reais em andamento.
  • Ficou claro que cada conexão recebe uma porta externa própria, não um IP escondido.
  • NAT foi entendido como tradução rastreável, não como mágica.

Rollback e limites

Os comandos de hoje (ip addr, curl, conntrack -L) são todos de leitura, sem risco. O cuidado real é conceitual: entender que a tabela de tradução é temporária e específica por conexão — isso evita confusão mais adiante quando você configurar SNAT e DNAT manualmente.

Alternativa correta: A. Nesta aula, a explicação certa foi porta externa diferente por conexão, mapeada na tabela de tradução. O ponto central do caso é este: NAT muda o envelope do pacote, mas precisa lembrar para quem entregar a resposta.
