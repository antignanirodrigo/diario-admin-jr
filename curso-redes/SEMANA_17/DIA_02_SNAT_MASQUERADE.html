SNAT/Masquerade: uma Regra para a Rede

quando a regra é por padrão de tráfego, não multiplique por máquina

ANTES DE ALTERAR, OBSERVE. DEPOIS DE ALTERAR, VALIDE.

1. O chamado

"Vou criar uma regra por computador para sair na internet." Quadro cheio de post-its: SNAT 192.168.10.15, SNAT 192.168.10.17, SNAT 192.168.10.18... 50 regras planejadas. Mais trabalho, mais arriscado, difícil de manter, fácil de esquecer alguém. Existe um jeito muito mais simples.

💡 Passa o mouse nas palavras destacadas pra ver uma dica rápida — clica se quiser a explicação completa com analogia.

2. Antes de ver as opções — tenta responder

🧠 Recall ativo: qual é a diferença entre SNAT fixo e masquerade, e por que masquerade costuma ser a escolha certa numa rede doméstica ou pequena empresa?
SNAT fixo exige que você declare o IP público manualmente. O masquerade usa o IP ATUAL da interface de saída, se adaptando sozinho se esse IP mudar (comum em conexões dinâmicas). Uma regra cobre a sub-rede inteira, sem precisar de 50 regras individuais por máquina.

5. Ferramentas e leitura da evidência

ComandoO que faz
nft add table ip natCria a tabela dedicada a regras de NAT.
nft add chain ip nat postroutingCria a chain de pós-roteamento, onde SNAT/masquerade se aplica.
masqueradeAção que traduz a origem para o IP atual da interface de saída.
$ sudo nft add table ip nat
$ sudo nft add chain ip nat postrouting '{ type nat hook postrouting priority srcnat; policy accept; }'
$ sudo nft add rule ip nat postrouting \
    oifname wan0 ip saddr 192.168.10.0/24 masquerade

5.1 O sênior limpa o quadro de 50 post-its de SNAT por host, dizendo que masquerade aplica a lógica certa no ponto certo: a saída

Um colega acha que, mesmo assim, ter regras individuais por host daria mais controle.

QUESTÃO 3 de 3 — detalhe que confunde todo iniciante

5.2 "Se o IP público mudar (conexão dinâmica), a regra de masquerade precisa ser reescrita?"

Um colega acha que toda vez que o provedor troca o IP público, alguém precisa atualizar a regra manualmente.

Por que isso não é necessário com masquerade?
💡 Analogia do Sênior para Fixar: Aplicar as boas práticas de 02 SNAT MASQUERADE é como o protocolo de segurança da aviação: elimina pontos únicos de falha e garante previsibilidade operacional.

6. Procedimento profissional

  1. Identifique o padrão de tráfego real: toda a sub-rede saindo por uma interface específica.
  2. Configure uma única regra masquerade cobrindo essa sub-rede, na chain postrouting.
  3. Nunca crie regras individuais por host quando o padrão é uniforme para toda a rede.
  4. Valide com conntrack -L, confirmando múltiplos clientes usando o mesmo IP público.
  5. Documente a regra única, facilitando auditoria e manutenção futura.

7. Laboratório guiado — marca conforme for testando

Segurança: execute os testes apenas em VM descartável e confirme nomes de discos, hosts e arquivos antes de cada comando.
  1. Em VM de laboratório com duas interfaces (LAN e WAN), crie a table e chain de NAT.
    Resultado esperado: table e chain criadas sem erro.
  2. Adicione a regra masquerade cobrindo a sub-rede da LAN, saindo pela interface WAN.
    Resultado esperado: regra adicionada, visível em nft list ruleset.
  3. De uma máquina cliente na LAN, acesse a internet (ou um destino simulado) e confirme com conntrack -L.
    Resultado esperado: tradução visível, IP de origem trocado pelo IP da interface WAN.
    🧑‍🏫 Aqui entra o Mentor (em breve): se a tradução não aparecer, este é o ponto onde o chat com o Sênior-IA vai ajudar a verificar se o roteamento e o encaminhamento de pacotes (ip forward) estão habilitados.
  4. Teste com duas máquinas clientes simultaneamente e confirme portas diferentes na tabela de tradução.
    Resultado esperado: ambas usando o mesmo IP de saída, portas diferentes.
  5. Documente a regra única no runbook de rede — reproduzindo o painel 6 da prancha de hoje.
    Resultado esperado: registro claro: SNAT/masquerade ativo, sem regra por host.

8. Validação e encerramento

  • Uma única regra masquerade cobre toda a sub-rede, não uma por host.
  • A tradução foi confirmada na prática via conntrack -L, com múltiplos clientes.
  • A regra se adapta automaticamente ao IP atual da interface de saída.
  • A configuração foi documentada de forma clara e auditável.

Rollback e limites

Uma regra de masquerade pode ser removida com nft delete rule, usando o handle mostrado por nft -a list ruleset. O cuidado real é sempre pensar por padrão de tráfego (sub-rede, interface) antes de pensar por host individual — evita trabalho desnecessário e reduz superfície de erro.
💡 Sobre repetição espaçada: "uma regra por padrão, não por host" conecta com a Semana 15 (masquerade em vez de regra por máquina é análogo a masquerade cobrindo sub-rede em vez de regra por porta) — mesma disciplina de generalizar corretamente. O Anki vai conectar os dois.

9. Resposta final

Alternativa correta: A. Nesta aula, a configuração certa foi uma única regra de masquerade cobrindo a sub-rede inteira, na saída pela interface WAN. O ponto central do caso é este: quando a regra é por padrão de tráfego, não multiplique por máquina.

🔓 O que você desbloqueou hoje

Capacidade de configurar NAT de saída com uma única regra bem pensada, em vez de multiplicar regras desnecessárias. Amanhã você aprende o oposto: DNAT, que permite publicar um serviço interno pra fora — e por que port forwarding sozinho não é a mesma coisa que permissão de firewall.
