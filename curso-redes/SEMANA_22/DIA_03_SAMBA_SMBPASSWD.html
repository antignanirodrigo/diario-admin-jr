1. O chamado

Chamado #2203: "Segui exatamente o Dia 2, valid users = joao está certinho no smb.conf, mas quando o Windows pede senha, nenhuma senha que eu tento funciona — nem a senha Linux do joao." Isso é esperado: o usuário joao existe no Linux, mas nunca foi cadastrado na base de credenciais do Samba. É exatamente pra isso que existe o comando smbpasswd.

2. Antes de ver as opções — tenta responder

🧠 Recall ativo: smbpasswd -a joao CRIA um novo usuário Linux chamado joao, ou faz outra coisa?
smbpasswd -a joao NÃO cria um usuário Linux — ele exige que joao JÁ EXISTA como usuário do sistema (criado antes com useradd). O que o comando faz é adicionar uma entrada pra esse usuário existente na base própria de credenciais do Samba, pedindo uma senha específica pra autenticação SMB. Se você rodar smbpasswd -a pra um usuário que não existe no Linux, o comando falha — a ordem importa: primeiro o usuário Linux, depois a credencial Samba.

Um colega acha estranho poder digitar uma senha diferente da senha Linux quando o smbpasswd pede pra criar a credencial.

Por que a senha cadastrada com smbpasswd pode ser completamente diferente da senha Linux do mesmo usuário, sem nenhum problema?

6. Procedimento profissional

  1. Confirme que o usuário Linux já existe com id <usuario> antes de qualquer coisa.
  2. Cadastre a credencial Samba com sudo smbpasswd -a <usuario>.
  3. Confirme o cadastro com pdbedit -L, listando os usuários da base Samba.
  4. Teste a autenticação real com smbclient //servidor/compartilhamento -U <usuario>.
  5. Documente que a senha Samba é independente da senha Linux — evita confusão futura de suporte.

7. Laboratório guiado — marca conforme for testando

Segurança: execute os testes apenas em VM descartável e confirme nomes de usuários, discos e arquivos antes de cada comando.
  1. Numa VM de laboratório, tente smbpasswd -a pra um usuário que ainda não existe no Linux, e observe o erro.
    Resultado esperado: mensagem de erro indicando que o usuário não existe.
  2. Crie o usuário Linux com useradd, e só então rode smbpasswd -a pra ele.
    Resultado esperado: senha Samba cadastrada com sucesso.

    Resultado esperado: login Linux com uma senha, login Samba com outra, sem conflito.

8. Validação e encerramento

  • smbpasswd -a exige que o usuário Linux já exista — ele não cria conta nova.
  • A senha Samba é independente da senha Linux, mesmo usuário, dois sistemas de credencial.
  • pdbedit -L confirma quem está cadastrado na base do Samba.
  • smbclient é a ferramenta de teste rápido de autenticação, sem precisar de máquina Windows.

Rollback e limites

Remover uma credencial Samba com smbpasswd -x é reversível — basta cadastrar de novo com -a. O cuidado real é confusão de suporte: usuários costumam achar que "trocar a senha" significa trocar a senha Linux, quando na verdade pode ser necessário trocar a senha Samba separadamente (smbpasswd, sem -a, troca a senha de quem já está cadastrado).
💡 Sobre repetição espaçada: "duas bases de credencial independentes, mesmo usuário" é o mesmo padrão de UID/GID divergente entre máquinas (Semana 21) — identidade não é automática entre sistemas diferentes, precisa ser reconciliada explicitamente. O Anki vai conectar os dois.

9. Resposta final

Alternativa correta: A. Nesta aula, o comando certo foi sudo smbpasswd -a joao, cadastrando a credencial na base própria do Samba. O ponto central do caso é este: o usuário já existe no Linux — falta só ele existir também na base de credenciais do Samba.

🔓 O que você desbloqueou hoje

Capacidade de cadastrar e gerenciar credenciais Samba independentes da autenticação Linux. Amanhã você aprende sobre a camada extra de permissão do Samba, combinada com a permissão Unix tradicional — as duas precisam concordar antes de qualquer acesso funcionar.
