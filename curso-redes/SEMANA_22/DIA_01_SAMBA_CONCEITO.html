🔓 Privilégio de hoje: entender por que Samba existe ao lado do NFS, não no lugar dele. Você ganha a distinção central: dois protocolos de compartilhamento de arquivo diferentes, cada um nativo de um mundo — e por que escolher o errado significa pedir pro cliente instalar software extra.

2. Antes de ver as opções — tenta responder

🧠 Recall ativo: por que um cliente Windows não consegue simplesmente montar um export NFS do jeito que um cliente Linux faz, sem nenhum software adicional?
NFS e SMB são protocolos de rede DIFERENTES, cada um com seu próprio jeito de negociar conexão, autenticação e transferência de arquivo. O Windows, por padrão, só fala SMB nativamente — ele não "entende" NFS sem instalar um cliente NFS separado (que existe, mas é extra, menos comum, e menos integrado que o suporte nativo a SMB). Samba resolve isso na ponta do SERVIDOR: o Linux passa a falar o idioma que o Windows já entende de fábrica, sem exigir nada extra do lado do cliente.

6. Procedimento profissional

  1. Diante de um chamado de compartilhamento de arquivo, identifique primeiro o sistema operacional do cliente.
  2. Para clientes Linux/Unix, NFS (Semana 21) costuma ser a opção mais nativa e simples.
  3. Para clientes Windows, Samba é a opção que evita instalar software adicional no cliente.
  4. Confirme os serviços smbd e nmbd ativos no servidor antes de configurar qualquer compartilhamento.
  5. Lembre desde já que autenticação Samba é uma base separada da autenticação Linux — isso será configurado no Dia 3.

  1. CENÁRIOAção: Instale o Samba na VM de laboratório e confirme que os dois serviços essenciais (smbd e nmbd) subiram, além da porta SMB escutando.
    sudo apt update && sudo apt install -y samba sudo systemctl status smbd nmbd --no-pager ss -tlnp | grep -E ':445|:139'
    🔍 Detalhar esse comando
    ss
    Substituto moderno do netstat — lista sockets de rede ativos no sistema.
    -t
    Mostra apenas conexões TCP (o protocolo usado por SMB).
    -l
    Mostra apenas sockets em modo LISTEN — portas esperando conexão, não conexões já estabelecidas.
    -n
    Mostra endereços e portas em formato numérico, sem tentar resolver nomes — mais rápido e sem depender de DNS.
    -p
    Mostra o processo (PID e nome) dono de cada socket — exige sudo pra aparecer completo.
    grep -E ':445|:139'
    Filtra a saída só pelas linhas que mencionam a porta 445 (SMB moderno) ou 139 (NetBIOS/SMB legado) — as duas portas que o Samba pode usar.
    Resultado esperado: smbd e nmbd aparecem como "active (running)", e a porta 445 (e geralmente a 139) aparecem em LISTEN na saída do ss.
    Por que fizemos isso: sem confirmar que os dois serviços realmente subiram e a porta está escutando, qualquer teste de acesso do Windows depois vira suposição — você precisa da evidência de que o servidor está pronto pra receber conexão SMB antes de ir pro cliente.
    Cilada comum: instalar isso em servidor de produção só pra testar. Só em VM descartável — e confirme que não há firewall bloqueando a porta 445 na rede do laboratório.
    Se o seu resultado foi diferente
    "Unable to locate package samba" → atualize a lista de pacotes primeiro com sudo apt update, ou confirme que o repositório universe está habilitado (Ubuntu): sudo add-apt-repository universe.
    nmbd aparece como "inactive" ou "failed" → distros recentes às vezes desabilitam nmbd por padrão (NetBIOS é menos necessário com DNS moderno). Ative com sudo systemctl enable --now nmbd. Sem ele, a resolução de nome NetBIOS pode falhar, mas acesso via IP direto no Windows ainda funciona.
    a porta 445 não aparece no ss → confirme que smbd realmente está "active (running)" primeiro — se o serviço caiu, rode sudo journalctl -u smbd -n 30 pra ver o motivo antes de tentar de novo.

8. Validação e encerramento

  • NFS e SMB são protocolos diferentes — Windows fala SMB nativamente, não NFS.
  • Samba implementa SMB no Linux, permitindo compatibilidade nativa com clientes Windows.
  • Samba mantém uma base de credenciais própria, separada da autenticação Linux comum.
  • SMB é a família de protocolo; CIFS foi um dialeto específico mais antigo dela.

Rollback e limites

Instalar o pacote Samba e confirmar os serviços é uma operação de baixo risco e reversível (apt remove samba, se necessário). O cuidado real chega quando compartilhamentos reais forem configurados (Dia 2 em diante) — cada compartilhamento é uma superfície de acesso à rede que precisa ser deliberada, igual às regras de firewall e export NFS já vistas.
💡 Sobre repetição espaçada: "protocolo nativo de cada mundo" é a mesma lógica de escolher a ferramenta certa pro público certo, já vista em várias camadas do curso — vale reforçar esse princípio de adequação, não só o caso específico NFS vs. SMB. O Anki vai conectar essa ideia à Semana 21.

9. Resposta final

Alternativa correta: A. Nesta aula, a solução foi instalar e configurar Samba no servidor Linux, criando compatibilidade nativa com o Windows. O ponto central do caso é este: o mesmo problema do NFS, resolvido no idioma que o Windows já fala nativamente.
